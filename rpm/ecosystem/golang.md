# Go Packaging

## When to Load

Load when the spec uses `%gometa`, `%goprep`, `%gobuild`, `%{goipath}`,
BuildRequires `go-rpm-macros` or `go-vendor-tools`, the package is named
`golang-*`, or the sources contain `go.mod`.

References:
- https://docs.fedoraproject.org/en-US/packaging-guidelines/Golang/
- https://fedora.gitlab.io/sigs/go/go-vendor-tools/

## Package Types

| Type | Name | Notes |
|------|------|-------|
| Library (unbundled) | `golang-<importpath-derived>` | Ships sources as `golang-...-devel` (noarch) under `%{gopath}`; generated by go2rpm |
| Application (unbundled) | upstream name, or `golang-...` with binaries | Built against `golang-*-devel` packages |
| Application (vendored) | upstream name | Built against a vendor tarball, license handling via go-vendor-tools |

Fedora allows vendoring for Go applications. New applications are
commonly packaged vendored using go-vendor-tools; libraries are packaged
unbundled. Check current guidelines when it matters, as this policy has
evolved.

## Standard Spec Shape (unbundled)

```
%global goipath github.com/example/foo
Version:        1.2.3

%gometa -f

Name:           %{goname}
Release:        %autorelease
Summary:        ...
License:        MIT
URL:            %{gourl}
Source:         %{gosource}

%description %{common_description}

%gopkg

%prep
%goprep

%generate_buildrequires
%go_generate_buildrequires

%build
%gobuild -o %{gobuilddir}/bin/foo %{goipath}/cmd/foo

%install
%gopkginstall
install -m 0755 -vd                     %{buildroot}%{_bindir}
install -m 0755 -vp %{gobuilddir}/bin/* %{buildroot}%{_bindir}/

%check
%gocheck

%gopkgfiles
```

Vendored packages with go-vendor-tools add a vendor archive as a second
Source, `%goprep -A` (do not delete vendor), the
`%go_vendor_license_buildrequires`, `%go_vendor_license_install`, and
`%go_vendor_license_check` macros, and use
`%{go_vendor_license_filelist}` in `%files`. License expressions come from
`go_vendor_license report expression`. Exact macro options vary between
go-vendor-tools versions; check the version in the target buildroot.

## Review Checks

- [ ] Spec is go2rpm-generated or follows its structure
- [ ] Binaries built with `%gobuild`, not raw `go build` (`%gobuild` passes
      distribution build flags, a GNU build-id, and `-trimpath`-equivalent
      settings needed for debuginfo)
- [ ] `ExclusiveArch: %{golang_arches}` (or `%{golang_arches_future}`)
      present for arch-specific packages
- [ ] Unbundled: `%go_generate_buildrequires` used; `golang(...)`
      BuildRequires not hand-maintained without reason
- [ ] Vendored: vendor archive generation is documented and reproducible
      (`go_vendor_archive create` with a checked-in `go-vendor-tools.toml`)
- [ ] Vendored: `License:` covers all vendored modules, and
      `%go_vendor_license_check` runs in `%check`
- [ ] Vendored: `bundled(golang(...))` Provides are present (generated by
      go-vendor-tools from `vendor/modules.txt`)
- [ ] Test exclusions use `%gocheck -d <dir>` / `-t <tree>` / `-r <regex>`
      with a comment, not removal of `%check`
- [ ] Version-embedding `-ldflags -X` values set via `LDFLAGS` before
      `%gobuild` rather than replacing `%gobuild` flags

## Build Failures

| Symptom | Likely cause | Fix |
|---------|-------------|-----|
| `cannot find package` / `no required module provides package` | Unbundled build missing a `golang-*-devel` BuildRequires, or module path mismatch between `go.mod` and `%{goipath}` | Check `%go_generate_buildrequires` output; verify `goipath` matches `go.mod` module path |
| Build tries to download modules (`dial tcp ... proxy.golang.org`) | Module mode used without vendor dir or without the GOPATH layout from `%goprep` | Use `%goprep` (and `-A` for vendored); do not override `GOFLAGS`/`GO111MODULE` |
| `inconsistent vendoring` | `vendor/modules.txt` does not match `go.mod` (patched `go.mod` after vendoring, or wrong vendor tarball version) | Regenerate the vendor archive after patching `go.mod` |
| `Missing build-id in ...` / debuginfo errors | Built with raw `go build` or upstream Makefile | Replace with `%gobuild`, or pass `%{gobuildflags}`-equivalent flags to the upstream build |
| Tests fail only in koji/mock | Network access, writable `$HOME`, timing, root-only operations | Exclude specific tests via `%gocheck -r` / `-d` with a comment |
| Failure after Go toolchain bump | Stricter `go vet` run during `go test`, removed deprecated APIs, `go.mod` `go` / `toolchain` directive newer than installed Go | Patch upstream code or `go.mod`; a `toolchain` directive must not trigger downloads |
| `%go_vendor_license_check` fails | New vendored module with a license not yet mapped, or License tag out of date | Update `License:` from `go_vendor_license report expression`; add overrides in `go-vendor-tools.toml` for undetectable licenses |
| 32-bit failures | `int` overflow on constants, atomic 64-bit alignment on i686/armv7 | Patch code; check whether arch is even in `%{golang_arches}` |

## False Positives

- `golang-*-devel` packages shipping `.go` sources under `%{gopath}`:
  required by Go packaging, not "shipping source code by mistake"
- Missing `%{?_isa}` on `golang(...)` dependencies: they are noarch sources
- Go binaries being statically linked against Go dependencies: inherent to
  the language; not a bundling violation for unbundled packages
- Long `License:` expressions in vendored packages: expected
- `%gometa` defining `Name`/`URL`/`Source` indirectly (`%{goname}`,
  `%{gourl}`, `%{gosource}`): standard go2rpm pattern
- rpmlint `unstripped-binary-or-object` / `statically-linked-binary` on
  Go binaries: inherent to Go
